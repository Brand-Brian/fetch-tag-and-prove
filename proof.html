Two layers, running at once

A tracked link is fast and precise but fragile. A code is slower but almost unbreakable. Running both is what makes attribution survive real traveller behaviour.

Layer 1 — the tracked link

Every creator-property pairing mints its own short link. It carries a click ID from the bio, the Story sticker or the auto-DM straight through to the property's own booking page, where a confirmation pixel closes the loop.

  • Instant, exact, and invisible to the traveller
  • Records the tap even when the booking comes later
  • Breaks on: device switches, in-app browsers, cleared cookies, long delays

Layer 2 — the code

The same pairing gets a unique code. It rides on a screenshot, survives a switch from phone to laptop, and still works nine days later. If the code is on the reservation, the creator gets credit. Full stop.

  • Survives everything the click chain can't
  • Readable by any property, with no technology at all
  • Doubles as the manual verification path during the pilot

The monthly reconciliation loop

During the pilot, verification is deliberately manual. It's slower, and it's the only way to be certain the number is real before it gets automated.

Step 1Statement out

At month end FETCH generates a statement per property: every booking claimed against a code or tracked link, with the creator attached.

Step 2Property confirms

The property ticks the stays that actually completed. Anything unconfirmed stays unbilled — silence never becomes a charge.

Step 3Cross-check

Confirmations are matched back against the tap data. Mismatches get looked at by a person, not resolved by an algorithm.

Step 4Payout

Commission is invoiced once and the creator's 5% is paid in cash. The record is visible to both sides afterwards.

Later, PMS checkout webhooks (Guesty, Hostaway) replace steps 1–3 automatically. The code layer stays live permanently — it's the thing that survives when the click chain doesn't.

Why this becomes the moat

Every verified booking adds a row nobody else has: this creator, this property, this destination, this audience — this conversion rate.

Nobody else has the last mile

UGC platforms stop at views. Affiliate networks stop at clicks. The completed direct booking is the only event that proves value, and it's the one nobody was tracking.

It compounds per region

Density means real conversion rates for a corridor, not a global average that describes nothing. Each region proven makes the next one faster to open.

It reprices creator work

Once you can show what a post is worth in bookings, flat sponsorship fees start to look like guesswork — for both sides.

It's not a booking engine

FETCH never holds payment and never becomes merchant of record, so no property has to weigh giving up their guest to get the data.
